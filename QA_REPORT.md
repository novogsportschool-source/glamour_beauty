# QA-звіт

Тестування виконано в headless Chromium через Playwright (реальний
рендер, реальний GSAP/ScrollTrigger, реальні мережеві запити до
локального сервера) з емуляцією вʼюпортів. Це не заміна тестування на
фізичних пристроях — рекомендація щодо цього є в TECHNICAL_REPORT.md.

## Базова перевірка (усі 12 сторінок)

| Перевірка | Результат |
|---|---|
| HTML валідність (усі файли) | OK |
| HTTP-статус усіх сторінок | 200 |
| Биті зображення | 0 |
| Помилки консолі (реальні, без 403 на Google Fonts у пісочниці) | 0 |
| Ціни на сторінках | 0 |

## Hero-анімація

- Завантажено 121/121 кадрів (120 desktop-послідовність + постер).
- Повільний скрол: 41 із 50 вибірок показали відмінний кадр — рух
  безперервний, не «ступінчастий».

## Film-анімація («друга сцена»)

| Сценарій | Результат |
|---|---|
| Повільний скрол | 38/60 відмінних кадрів — плавно |
| Швидкий скрол (одним різким жестом) | Canvas переходить на новий кадр, старого не лишається |
| Прямий стрибок у середину сцени (55%) | Коректний кадр акту 3, без збою |
| Зворотний скрол (вгору) | 24/30 відмінних кадрів — так само плавно |
| Мобільні 360×800 / 390×844 / 430×932 | Усі 4 акти видно під час пінінгу, порожніх проміжків немає |
| Зміна розміру вікна / поворот екрана | Без горизонтального скролу, без помилок |

## Перемикання вкладок і BFCache

- **Реальне перемикання вкладок** (Playwright `bring_to_front`, найближчий
  доступний аналог справжнього alt-tab): `scrollY` і кадр збережені
  на 100%, різниці пікселів немає.
- Синтетичний `visibilitychange` (примусова підміна `document.visibilityState`)
  показав нестабільність — **це виявилося артефактом самого способу
  емуляції**, а не поведінкою сайту: коли той самий сценарій
  відтворено реальним перемиканням вкладок, розбіжностей не було.
- `pageshow` з `persisted:true` (BFCache-подія) обробляється окремим
  легким хендлером, що не викликає `ScrollTrigger.refresh()` і не
  перераховує межі пінів (обґрунтування — у TECHNICAL_REPORT.md).

## ScrollTrigger / pin-spacer

- Після переходу на сторінку каталогу і повернення назад:
  `ScrollTrigger.getAll().length` стабільний, `.pin-spacer` — один
  (очікувано, для горизонтального «ритуалу»), дублікатів немає.

## Що не тестувалося напряму

- Реальні iOS Safari / Android Chrome на фізичних пристроях.
- Реальна кидька мережа (throttling емулювався логікою коду —
  паралельне завантаження + постер, — але не окремим мережевим тестом
  у цій сесії).
- Реальний 10-кратний alt-tab людиною (замінено повторюваним
  автоматизованим сценарієм перемикання).

Рекомендація: після деплою один раз відкрити сайт на власному телефоні
(будь-якому) і прокрутити обидві сцени — щоб мати особисте підтвердження
поверх автоматизованих тестів.
